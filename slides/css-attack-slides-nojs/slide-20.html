WHAT YOU ACTUALLY SHIP

length × alphabet — linear. ~13 × 37 ≈ 480 rules, spread across the rounds.

WHAT YOU NEVER NEED

every permutation of the value: alphabet^length = 37^13 ≈ 10^20. Impossible — and unnecessary.

The attacker's server extends the prefix and serves each round via @import — no JavaScript on the victim.

This slide exists to kill the first question every engineer asks: "surely you'd need every possible permutation of the string?" No — and that's the elegant part. Walk the three steps: (1) you have a known prefix; (2) you ship ONE rule per candidate for the NEXT position only — about 37 rules for [a-z0-9-], not for the whole string; (3) exactly one matches because the href can only continue with one character, so exactly one background request fires and the server learns that character. Then you extend the prefix and repeat. The cost is length x alphabet (linear, ~480 rules here), NOT alphabet^length (37^13, astronomically impossible) — that contrast is the whole point of the slide, so land it. Finally: the rounds are sequenced by the attacker's server via @import chaining, so none of this needs JavaScript on the victim. If someone asks "how does round 2 know round 1's answer without JS?" — the server saw the beacon from round 1 before it served round 2's stylesheet. ~75 seconds; this is the technical heart, don't rush it.
