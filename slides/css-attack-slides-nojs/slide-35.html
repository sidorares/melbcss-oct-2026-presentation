What actually helps

You don't sanitize your way out. You isolate.

ISOLATE IT

Render untrusted HTML in a sandboxed iframe. No shared trust boundary, nothing to break out of.

CUT THE REQUESTS

Route images through a proxy, block data: URLs, and don't allow-list domains an attacker can use.

ALLOW-LIST CHARACTERS

Validate names and keywords with a strict character allow-list — not a blocklist — to survive CSSOM mutation.

REVIEW & PATCH

Read CSS diffs like code. Watch your supply chain & themes. Keep the browser updated — the engine bugs are real.

Blocklists lose to parser differentials. Isolation removes the game entirely.

The constructive payoff — give them something to do Monday. The through-line of every failure in this talk is a blocklist trying to out-guess a browser, which it can't; so the headline is "isolate, don't sanitize." Four concrete moves: (1) sandboxed iframes so untrusted content shares no trust boundary with your UI; (2) image proxy + block data: URLs + no attacker-usable allow-listed domains; (3) when you must validate, allow-list characters not keywords, which defeats the CSSOM mutation trick; (4) treat CSS as code in review, watch dependencies and community themes (callback to MelbCSS), and patch browsers because the engine UAF is not hypothetical. ~55 seconds.
