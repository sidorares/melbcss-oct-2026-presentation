WHEN CSP BLOCKS EVERY REQUEST

Reading needs no network. Sending rides a click.

1 · READ IT — zero network

A local font per digit resizes just that digit:

@font-face{src:local('Courier New');
unicode-range:U+0030;descent-override:200%}

Flip each digit's font on in turn — the text block grows a fixed step per matching digit. Measure the height in pure CSS (container queries) → how many of each digit. No font fetched, no script.

2 · SEND IT — no request

Pre-place one link per possible answer; each href encodes a digit-count.

The oracle makes the matching link fill the screen (inset:0) and shoves the rest off (inset:100%).

The victim clicks anything → clicks that link → it navigates out carrying the token.

A resource CSP blocks fetches. It blocks neither pure-CSS measurement nor a click-driven navigation.

Explainer for the "no request" exfil, because it's the slipperiest beat. Two halves. READ: the attacker never fetches anything — local fonts (src: local()) resized per digit via descent-override make the text block taller when a given digit is present; CSS container queries read that height back as a number, so CSS alone counts the digits. SEND: there's no fetch either — every possible answer is pre-laid as a link whose href encodes a digit-count; the oracle result makes exactly the matching link full-screen (inset:0) and the rest offscreen (inset:100%), so any victim click selects it and NAVIGATES to the attacker. The key correction vs the old headline: data DOES leave — as a navigation on a click — but no resource is ever fetched, which is what a CSP governs. ~70 seconds; walk both halves slowly.
