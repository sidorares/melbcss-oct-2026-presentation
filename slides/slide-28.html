WHY “BLOCK EVERY REQUEST” ISN’T ENOUGH

Exfiltration isn’t one problem. It’s two.

THE ASSUMPTION

Leaking data means making a network request.

So a strict CSP that blocks every outbound request should make the secret impossible to get out.

“No request can leave → nothing leaks.”

READ — MEASURE, DON’T FETCH

The secret changes the page’s layout. A font that applies to just one digit makes matching digits taller — and CSS reads that height back as a number.

Only fonts the browser already has. Nothing is downloaded.

SEND — NAVIGATE, DON’T REQUEST

Every possible answer is pre-placed as a link. The measurement slides the matching link under the cursor and shoves the rest off-screen.

The victim’s own click carries it out — a page navigation, not a fetch.

WHAT ACTUALLY LEAKS

One pass tells you how many of each digit — not their order. Position comes from the same narrow-one-character-at-a-time trick as the href leak (slide 20), repeated per position.

A CSP governs fetches. Measurement and navigation aren’t fetches — so the box it draws has no wall on this side.
